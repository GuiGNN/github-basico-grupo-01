# Conhecendo o GitHub e criação de conta


Guia simples para quem está começando.

---

## 1. O que é GitHub?

**GitHub** é uma plataforma de desenvolvimento que salva projetos na nuvem. A principal função dele é salvar, armazenar, administrar e compartilhar códigos com outros usuários.

Ele usa o **Git**, um sistema de controle de versão. Isso quer dizer que cada alteração feita no projeto fica registrada, e dá para voltar a uma versão anterior se algo der errado.

**Git e GitHub não são a mesma coisa:**

| Git | GitHub |
|---|---|
| Ferramenta de controle de versão | Serviço online que usa o Git |
| Funciona no próprio computador | Funciona na internet, pelo navegador |
| Registra o histórico dos arquivos | Guarda os projetos na nuvem e facilita o trabalho em grupo |

---

## 2. O que é um repositório?

**Repositório** é o espaço onde ficam guardados os arquivos de um projeto e o histórico de alterações de cada um deles. É o elemento mais básico do GitHub.

> **Exemplo:** é como uma pasta na nuvem que lembra de tudo o que já mudou dentro dela.

### Público ou privado?

| | Público | Privado |
|---|---|---|
| Quem vê | Qualquer pessoa | Só você e quem foi convidado |
| Quem altera | Só quem tem permissão (os outros podem sugerir mudanças) | Só você e quem foi convidado |
| Indicado para | Projetos que podem ser mostrados a todos | Projetos em desenvolvimento ou com informações que não devem ser divulgadas |

**Atenção:** em repositório público, tudo fica exposto. Nunca publique senhas, chaves de API (códigos que dão acesso a serviços) ou dados pessoais.

---

## 3. Arquivos e versões

### README

O **README** (do inglês "leia-me") é o arquivo `README.md` que aparece na página inicial do repositório. É o manual de instruções do projeto: explica o que ele faz, como usar e como contribuir.

### Markdown

**Markdown** é uma forma simples de formatar texto usando símbolos, sem precisar de editor visual como o Word. Os arquivos terminam em `.md`.

| Para fazer | Escreva | Resultado |
|---|---|---|
| Título | `# Título` | Título grande |
| Subtítulo | `## Subtítulo` | Título menor |
| Itálico | `*texto*` | *texto* |
| Negrito | `**texto**` | **texto** |
| Lista | `- item` | • item |

### Commit

**Commit** (do inglês "registrar") é um ponto de salvamento, como em um jogo. Cada vez que você altera um arquivo, registra o commit com uma **mensagem curta** explicando o que mudou.

Exemplos de boas mensagens:

- "Adiciona dica sobre README"
- "Corrige erro de digitação no título"

### Histórico de alterações

É a linha do tempo com todos os commits do projeto. Mostra **quem** mudou **o quê** e **quando**, e ajuda a descobrir quando um erro (*bug*) apareceu.

---

## 4. Colaboração: branch, pull request e merge

Esse é o caminho que uma alteração percorre quando várias pessoas trabalham juntas:

1. **Branch** (ramificação): uma cópia do projeto para testar mudanças sem mexer na versão principal, chamada de **main**.
2. **Commit**: você faz a alteração na branch e a registra.
3. **Pull request** (pedido de incorporação): uma proposta para levar sua alteração para a versão principal. Os colegas veem a comparação entre as versões e comentam.
4. **Merge** (mesclar): depois da revisão, a alteração é incorporada à versão principal.

> **Exemplo:** é como fazer uma cópia de um trabalho para testar uma ideia, mostrar a um colega e, se ele aprovar, passar para o original.

---

## 5. Compartilhando o repositório

### Como convidar um colaborador

Colaborador é a pessoa autorizada a trabalhar no projeto.

1. Abra o repositório e clique em **Settings** (Configurações).
2. Clique em **Collaborators** (Colaboradores).
3. Clique em **Add people** (Adicionar pessoas).
4. Digite o nome de usuário do GitHub da pessoa e envie o convite.
5. A pessoa precisa **aceitar o convite** para ter acesso.

Em repositório público, também é possível compartilhar apenas o **link** da página.

### Cuidados ao publicar arquivos

**Nunca publique:**

- Senhas, tokens e códigos de autenticação.
- Dados pessoais (CPF, endereço, telefone, e-mail pessoal).
- Capturas de tela que mostrem informações pessoais.
- Materiais de outras pessoas sem autorização.

**Lembre-se:**

- Nunca compartilhe sua senha. Cada pessoa usa a própria conta.
- Apagar um arquivo não o remove do histórico. Se publicar uma senha por engano, troque-a imediatamente.
- Em caso de dúvida, não publique.
